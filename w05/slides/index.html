⏱️ loop "jalankan → baca hasil → perbaiki" Build pertama kadang merah — dan kalau iya, itu justru bagian terbaiknya. Di satu dry-run, pola --mount=type=bind bikin npm ci sukses tapi package.json tak pernah ada di image → RUN npm run build mati dengan ENOENT. perhatikan yang TIDAK ada di file itu — github Itu bukan kelalaian, melainkan keputusan. Server yang kamu butuhkan di mana saja (termasuk di luar folder repo, seperti §1(b)) tempatnya di scope user. Kapan JANGAN pakai MCP: pekerjaan deterministik & repetitif lebih murah lewat CLI langsung. Tiap server terpasang menambah token definisi tool di tiap sesi — MCP tidak gratis di context. Bahasan penuhnya di w06 (token/memory saving).
jebakannya — dan ini bukan hipotesis Kalau API key ditulis mentah di .mcp.json, sekali commit = key bocor ke seluruh tim. File ini tidak ada di .gitignore repo mana pun secara default, jadi git add . saja sudah cukup. Pola yang benar sudah kamu lihat dua kali hari ini: 'Authorization: Bearer ${SUPABASE_ACCESS_TOKEN}' (§4) dan 'CONTEXT7_API_KEY: ${CONTEXT7_API_KEY}' (§5) — berkutip tunggal, nilainya dari environment.
