§5b · ⭐ Mutation testing · test validationpanduan §5b10 menit
Rusak kodemu 3 mutasi · 1 per lapisan
KENAPAKalau test-mu tetap hijau, test itu tidak menjaga apa-apa.
JANGANDengan pekerjaan yang belum tersimpan. Cek dulu.
TERMINALcek dulu · dan rel pengaman
git status git checkout -- . # kalau kacau: kembalikan semua file terlacak
tugas QA di blok ini — kamu tidak mengetik, kamu memeriksa Untuk tiap mutasi, cari baris bukti (grep/git diff) di layar. Kalau Claude melompatinya, tegur: "mana bukti mutasinya terpasang? tunjukkan git diff dulu".
Kalau semua test tetap hijau, jangan langsung menyimpulkan test-mu lemah. Cek dulu: apakah kerusakannya benar-benar masuk ke file? Baru kalau sudah terbukti masuk, hijau itu berarti test-mu memang tidak menjaga titik tersebut.
Kenapa perl dilarang: di dry-run, perl -pi -e gagal dua kali tanpa disadari — sekali karena pola mengandung /, sekali karena {. Keduanya menghasilkan hasil yang terlihat seperti "test tidak menangkap mutasi", padahal kodenya tidak pernah berubah. Kalau alat gagal diam-diam, hasilnya hampir selalu tampak aman — dan itu arah kegagalan paling berbahaya.
Kenapa tidak pakai tool otomatis? Ada — Stryker Mutator. Kita manual karena muat di 10 menit, nol instalasi, dan yang diajarkan mekanismenya, bukan skornya. Di project kerjamu, pakai Stryker.
